Five of six were defects fixed before the v1 grid completed. Under the
current code, the only observed failure class is network loss, which is now
retried with connectivity gating.

**Risk at concurrency.** Rate-limit (429) and overload (529) errors are
**not** retried by the project code. Only transport and connection errors
become `StreamInterrupted`. After the SDK's own two retries, a 429 crashes the
run. That counts as a technical failure: the run never reached the gate, so
`run_heldout` re-runs it in the same position, but a council run lost late
costs up to its full length. The dev grid never ran two runs at once, so
there is no evidence on the account's headroom.

**Recommendation: `--max-parallel 7`.** Council calls within a run are
sequential, so this caps concurrent streams at 7. Baselines are submitted
first and clear in about a minute, so the seven council runs then run
together. The estimated wall time is the same as at 14 (one wave of councils
either way) with half the peak load. Going below 7 roughly doubles wall time
(at 4: 23–28 h expected). Before launch, check the organisation's
input/output token-per-minute limits for the model in the Anthropic console.
Seven concurrent council streams of about 5–10k output tokens per call is the
load to compare against.

**Estimates at `--max-parallel 7`** (dev timings; the long tail comes from
the 2f88 and 853f network gaps, so these are pessimistic):

|---|---:|---:|
| Lower bound (median council per round) | 2.0 h | 2.4 h |
| Expected (slowest of 7 councils per round) | 14.1 h | 17.6 h |

## Commit, tag and launch

Run from the repo root. **Step 1 is required.** `RunLogger` refuses every
run while anything is untracked, and Finder creates `.DS_Store` files, which
would turn every later run in a 14–24 h grid into a technical failure. The
other ignore lines and the inclusion of the review-pack files are my
recommendation. Adjust them before step 2 if you prefer.

**1. Ignore local artefacts**

    printf '%s\n' '.DS_Store' '.agents/' '.claude/' 'demo_bundle/' 'demo_bundle*.zip' 'outputs/' >> .gitignore

**2. Stage everything for the single commit**

    git add .gitignore \
      data/encodings/heldout/ \
      design_council/agents/baseline.py tests/test_baseline.py \
      design_council/measures/consistency.py design_council/measures/packs.py design_council/measures/depth.py \
      scripts/run_heldout.py scripts/analyse_heldout.py scripts/elimination_space.py scripts/measure_consistency_dev.py \
      docs/freeze_notes.md docs/PREREGISTRATION_HELDOUT.md docs/HELDOUT_SPEC_2026-10-10.md \
      docs/RESULTS_TEMPLATE_HELDOUT.md docs/DRAFT4_RESPONSES_D2_D3.md docs/GAP_CLOSURE.md \
      docs/HELDOUT_ENCODING_STOP_REPORT.md docs/HANDOFF_2026-10-11.md docs/p2p_three_way_matching.json \
      app.py scripts/make_review_pack.py data/review_packs/ docs/review_packs/

`packs.py` and `depth.py` (your `count_by_value` helper, which `packs.py`
uses) are required, because `measure_consistency_dev.py` imports `packs`.
The last line (app and review-pack work) is not a dependency. It is included
only so the tree is clean, and you can drop it and ignore those paths
instead.

**3. Check, then commit**

    git status --porcelain     # must print nothing
    git diff --cached --stat
    git commit -F /private/tmp/claude-501/-Users-shivanthameepage-design-council/7ad3d83e-7e95-4704-ad41-d6d584696f01/scratchpad/COMMIT_MSG.txt

**4. Tag the freeze**

    git tag -a prereg-heldout-2026-10-11 -m "Held-out pre-registration freeze: 7 encodings (57 steps, 70 rules, 16 open), v1 convention, run script, analysis helper"

There is no git remote, so the tag exists only on this machine. For a
timestamp others can check, also deposit the tagged pre-registration
somewhere external (for example OSF) before launch.

**5. Final dry run (every guard must show PASS)**

    .venv/bin/python scripts/run_heldout.py --set-name heldout-v1 --prereg-tag prereg-heldout-2026-10-11 --max-parallel 7 --dry-run

**6. Launch** (detached, machine kept awake, console output to a flat file in `runs/`)

    caffeinate -i nohup .venv/bin/python scripts/run_heldout.py --set-name heldout-v1 --prereg-tag prereg-heldout-2026-10-11 --max-parallel 7 > runs/_set-heldout-v1.console.log 2>&1 &

While it runs, do not edit, create or `git` anything in the repo. A dirty
tree makes every later run fail. Confirming that logs are written (§3) is
allowed:

    tail -n 5 runs/_set-heldout-v1.console.log

If it stops (failed round, or a laptop restart), re-run the step 6 command.
It resumes from the ledger. After every cell has stopped:

    .venv/bin/python scripts/analyse_heldout.py --set-name heldout-v1 --out docs/RESULTS_HELDOUT_tables.md
