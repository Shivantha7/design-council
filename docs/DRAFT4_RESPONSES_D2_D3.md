## Elimination space and the task-level ceiling (demand 2)

The development grid produced no eliminated or absorbed dispositions across 176 dispositions in either condition. This raises a fair question. A redesign that eliminates nothing may simply reorganise existing tasks, which is the task-level ceiling this study claims to move beyond.

Two points answer this. The first is that elimination is not the only route past the task-level ceiling. A redesign moves beyond the task level when it changes how the workflow achieves its outcome: merging steps, restructuring control points, or moving work between human and agent actors. Merged and restructured dispositions do this without removing a step. The depth metric was designed to capture these outcomes alongside elimination, and that design was set in the original proposal.

The second point is that the held-out set was encoded so that elimination is genuinely available. Across the seven held-out workflows, 16 of 57 steps (28%) carry no protecting rule and are listed as unconstrained by design. Several protecting rules were written to bind an outcome rather than a step. For example, three-way matching requires that quantity and price are both checked, not that they are checked in two separate steps, and financial statement release requires approval before release, not two distinct steps. These choices widen the space in which a step can be merged or removed without breaching a requirement.

This turns the zero-elimination result into a testable question. If the council still eliminates nothing when 28% of steps are open, that is a finding about the council and about rule-dense finance workflows, not a limit of the instrument. The development transcripts already point in this direction: the Maximalist role reasoned explicitly that no elimination was defensible on the development corpus. The held-out grid tests whether that judgement holds when the encoding makes elimination possible.

## Smallest effect size of interest and the conditional conclusion (demand 3)

In the development grid, depth separated cleanly only on vendor invoice processing. On the R2R and FPA workflows the gap between conditions fell within one depth quantum (0.125), which is within sampling noise at n = 3. Without a stated threshold, any held-out gap could be read as meaningful after the fact.

The smallest effect size of interest (SESOI) for transformation depth is therefore set at 0.2 before any held-out run. This is the equivalent of two steps in a ten-step workflow, which is the smallest change a finance function would recognise as a different way of working. A smaller gap may be real but is not practically meaningful for this study.

The decision rule is fixed in advance. The depth hypothesis is supported if the council's mean depth exceeds the baseline's by at least 0.2 on at least four of the seven held-out workflows.

If this is not met, the conclusion is also fixed in advance. The primary finding becomes the governance value of multi-agent deliberation rather than transformation depth. The study would then conclude that, in standardised and rule-dense finance workflows, deliberation adds value mainly through the controls it introduces, which a single agent does not produce, rather than through deeper structural change. The development phase already showed ten role-attributed governance controls in council outputs that were absent from every baseline run. The held-out coding procedure tests whether that pattern holds.

Sample size follows the same logic. Each cell runs at least four times and up to five, with a pre-registered rule that stops a cell at four runs if its depth in run 4 equals its depth in run 3. This reduces the noise problem seen at n = 3 while keeping the compute cost bounded.
